# 平台落地手册：小云雀 / MiniMax Design

> 这份文件回答一件事：**这条 MV 到底怎么在这两个平台上跑完。**
>
> ⚠️ 先说可信度：平台界面变化很快，下面写的是**按功能找的路径**，不是官方说明书。
> 具体按钮名称以你手上的版本为准。文末列了每一条结论的来源。

---

## 一、两个平台的关键差异（决定了流程怎么排）

| | 小云雀 | MiniMax Design |
|---|---|---|
| 形态 | 视频生成平台，Seedance 系 | **Agent 驱动的 Harness**：右侧对话区 / 中间画布 / 左侧 Skill 广场 |
| 切割能力 | **智能分镜 / 时间轴切割** | **AI 剪辑（自然语言指令）**——实测通过：「加字幕」「加转场」「**裁掉最后 2 秒**」 |
| 首尾帧 | **首尾帧模式**（上传首帧图 + 尾帧图） | 把尾帧作为**首帧参考**上传；或 3D 导演台里先摆好姿势 |
| 人物锁定 | 角色库 / 局部重改 | **资产中心**（人物锚、产品锚） |
| 工作方式 | 你逐条提交 | Agent **先反问确认**再动手 |
| 画布 | 常规 | 生成内容与上传素材**自动按流程连线** |

> MiniMax Design 一篇动手实测的原话：整个过程中用户能做的只有两件事——
> **确认，以及等**。所以「每一个步骤都让用户确认」跟它的工作方式天然合拍。

## 二、切割功能怎么用（这是用户点名要用上的）

### 关键点：**音乐由本技能切，画面由平台裁**

本技能按 **14.5 秒**切音乐（切点吸附小节线），但 MiniMax H3 的 `duration`
**只接受 4–15 的整数**，所以每一条都请求 **15 秒**，实出约 **15.083 秒**。

于是每条视频比它的音乐**长出约 0.58 秒**。这 0.58 秒不是浪费：

```
        音乐段 C1（14.226s）
        ├──────────────────────────┤
视频 C1  ├──────────────────────────┼──┤  实出 15.083s
                                    ↑
                              多出的 0.58s
```

**用法：把画面裁到音乐长度，把多出来的那 0.58 秒当作接缝重叠量**，
在**最快的那一下动作**里切——运动模糊会替你盖住不连续。

- **MiniMax Design**：一句自然语言就行——「把每条视频裁掉最后 0.6 秒」。
- **小云雀**：用时间轴裁剪，或让它按你给的时长重新生成。
- **通用平台**：任何剪辑软件，按 `cut_sheet.md` 里的毫秒数切。

### 平台自己的「智能分镜」要不要用？

**建议关掉或限制。** 有公开实测反馈说自动分镜容易**切得过碎**（"又吵又乱"）。
本技能已经把镜头数控制在**每段 2–4 个**、切点落在小节线上——
让平台再切一遍会破坏卡点。把分镜交给本技能的 `storyboard.md`。

## 三、尾帧续接怎么落地

链条：**上一段的最后一帧 = 下一段的第一帧。**

```
C1 ──尾帧──▶ C2 ──尾帧──▶ C3 ──尾帧──▶ C4
```

### 取帧的两条路

**A. 本地取（推荐，最快）**

```bash
python3 scripts/prism.py lastframe --video out/C1.mp4 --segment C1 \
    --describe "她右臂抬起，重心在左脚，背景是注册标记构成的平面世界"
```

工具降级：`ffmpeg` → **macOS 自带 AVFoundation** → 平台导出。
本机实测 AVFoundation 可用（PyObjC），能取到 2560×1440 的精确尾帧。

**B. 平台导出**

两个平台都能在时间轴上定位到最后一帧并导出图片。
存成 `workspace/frames/C1_last.png`，再跑 `prism.py chain` 重新挂链。

### ⚠️ 两条硬约束（必须遵守）

**1. 画风转换放在段内，不要一上来就换。**

尾帧会把上一段的**画风**也带进来。所以续接段的结构是：

```
0–1.5s   延续上一帧：同画风、同姿势，只做同族的连续动作
1.5s 后  世界在段内转场到本段的新画风
```

这样「接得上」和「换画风」同时成立，而且**转场本身成了视觉事件**——
这正是先锋 2D MV 要的东西。

**2. 续接段不要换姿势。**

一条第三方现场经验（**未经官方证实**，见下）：首尾两帧之间**垂直位移超过画面高度
12%** 时容易肢体撕裂，解决办法是插入过渡姿势而不是调参数。

我们据此写成保守的硬规则：**宁可不换姿势，也不要撕裂。**
所以 `chain_continuity` 是必填字段——写清楚「起手怎么接上一帧的姿势」。

## 四、上传顺序（按平台生成，见 `交付包/01-上传顺序与操作单.md`）

**模型按上传顺序编号，不读文件路径**，所以顺序不能错。

| 条 | 上传顺序 |
|---|---|
| C1 | [1] 人物参考图　[2] 三视图　[3] 音频段 |
| C2 及以后 | [1] 人物参考图　[2] 三视图　[3] **上一段尾帧**　[4] 音频段 |

渲染出来的提示词里对应：

- `<Picture 1>` 人物参考图（character reference）
- `<Picture 2>` 三视图（character turnaround reference）
- `<Picture 3>` 上一段尾帧（**first_frame reference**）
- `<Audio 1>` 原曲（fully_copy）

> **不要把文件名写进提示词。** 官方规则：模型按上传顺序编号，不读路径。

## 五、逐步骤确认怎么走

用户要求「每一个步骤都要让用户确认一下」。三个平台都一样：

```bash
python3 scripts/prism.py confirm --status        # 看还有哪些没确认
python3 scripts/prism.py confirm --step canon    # 确认某一步
python3 scripts/prism.py confirm --all           # 一次确认全部
```

确认点（`workspace/confirmations.json` 落盘，可查、可撤销）：

```
gate → analyze → lyrics → canon → threeview → styles → segments
  → prompt-01 … prompt-N      每一条提示词
  → chain-01  … chain-N       每一段的输出与尾帧
  → render → validate → pack
```

**未确认时 `render` 与 `pack` 会拒绝继续（exit 5）**，
除非显式加 `--unattended`（明确表示「我已经全部确认过了」）。

**MiniMax Design 用户注意**：它的 Agent 本来就会反问确认，
所以把上面的确认点直接当对话节奏走即可，不用另建流程。

## 六、两个平台各自的坑

### 小云雀

- **分镜容易过碎**：把每段镜头数钉死在 2–4 个，别让它自动细分。
- **局部重改适合改单帧/单段**，不适合改人物身份——身份靠 Canon + 参考图锁。
- 平台信息零散且随版本变，遇到名字对不上时**按功能找**：
  找「首帧/尾帧」、「裁剪/切割」、「角色一致性」。

### MiniMax Design

- **画布会自动连线**：把每段的音频段、尾帧、提示词放在同一条链上，不要散着扔。
- **资产中心可以存角色复用**：下一次开新项目时人物一致性会好很多。
- **语义级视频编辑目前不够准**：一篇实测报告里，「调暖色调」几乎没有肉眼变化，
  「换背景」时主体（耳机）变形了。
  → 结论：**不要靠事后改，要在提示词阶段就写对。**
- 成本参考（2026-08）：Starter 65 元/月 ≈ 10000 积分 ≈ 83 秒 H3 2K 视频。
  做一条 56 秒的 MV 大约要 4 条 15 秒生成，算得过来。
